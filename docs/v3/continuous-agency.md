# Continuous agency implementation

User request: 5 October 2026. This is an active implementation ledger, not a feature announcement. The baseline contains substantial earlier work; `evidence/2026-10-05-intent-runtime/starting-state.json` records the starting source hashes.

## Implementation rules

- Implement intent parsing, interrupt detection, graph reconciliation, scheduling, learning and resource admission directly in Rust. No remote AI service or downloaded model is required by these mechanisms.
- Use native system primitives for UI, authenticated IPC, process identity and device transport. A deterministic parser covers a documented command vocabulary; it is not general natural-language understanding or speech recognition trained from scratch.
- New fast paths must still resolve resources, obtain current authority, dispatch through the broker, independently verify effects and persist evidence. Preparation cannot grant authority. Unfinished intent cannot authorize a mutation.
- Keep work bounded on ordinary computers. Measure release builds and distinguish algorithm latency from OS, storage, transport and hardware latency.
- Show users concrete preparation, progress, correction, review and device/resource states. Never show a simulated device as connected or an unverified action as successful.

### Inference process-boundary foundation, 8 October

### Learned Mac application-control checkpoint, 7 October

- A successful learning probe now promotes its descriptor to Sage's registered `set_application_control` executor only after the durable before/change/restore observations establish exact restoration. Failed or unsettled probes stay non-executable. The descriptor remains evidence, never authority.
- The closed planner schema now represents finite JSON numbers as well as booleans. Only a Mac adapter that authenticated `application_control_v1` receives this tool in planning context or passes compiler checks; older clients cannot present an approval for this action or receive its execution request.
- When that negotiated Mac path is active, the local grammar can compile `Set <exact learned label> to <number|on|off>` directly, without inference. It requires one uniquely named, reversibly experimented descriptor; type mismatch and duplicate labels fail closed. The resulting proposal keeps user provenance and proceeds through the same fresh preparation, policy, approval, broker, and readback path.
- Before policy and approval, Core reloads the exact experimentally verified descriptor, checks the requested value's type and the current slider range/step, discovers the current signed foreground app, semantically binds the unique visible enabled control, and records fresh private OS evidence. The approval preview binds the signed code identity, app, control label/identity and requested value.
- After approval, Core repeats target and interface resolution and rejects changed app identity, control anchor or interface fingerprint before dispatch. The native adapter verifies its one-use app grant, checks the current foreground process and code signature, rebinds the exact accessibility control, and applies only the bounded Boolean or step-aligned number. A separate adapter read request supplies the fresh postcondition; Core verifies app, process, semantic anchor, control identity and exact typed value through the normal verifier and durable result path.
- This slice covers a single currently visible slider or toggle in the focused Mac app. It does not provide general UI action discovery, arbitrary app workflows, cross-platform execution, broad interface control, or 16 GB hardware acceptance. The Mac package build could not qualify in this Command Line Tools environment because the installed SwiftUI macro plugin is unavailable; the changed Swift source passed parser checks. Live accessibility and installed-app flows remain open.
- Validation: the latest `cargo test -p sage-core --lib -- --test-threads=4` run passes 344 tests with 10 ignored. The ignored pinned-tokenizer, model-metadata, and candidate-memory smoke tests were run separately with the exact candidate artifacts and passed. The six focused learned-control tests pass; `cargo check -p sage-core --lib`, strict all-target Clippy, `git diff --check`, Swift parser checks, and `scripts/test-native-control.sh` pass. These checks do not establish live Accessibility or installed-app behavior.

- **Local compiler and reflex:** Rust implements a bounded command grammar and leading-word Stop/Hold/Correction recognizer without a model or service. Typed input is debounced 120 ms; voice transcripts bypass that debounce. Sequenced previews show named actions before submission. On macOS, one complete app-opening step or one exact file read from a selected read folder can now start while a sequential voice request is still in progress; other partial actions remain preview-only.
- **Selective corrections:** local corrections preserve matching completed/in-flight steps, rewire unstarted successors, retire changed reads and accept replacements while other reads continue. The graph, request, receipt, revoked decisions and audit record commit together. New scopes still require new authorization. Changes to already dispatched mutations remain held for review; automatic app-close compensation is not implemented.
- **Scheduling:** up to four scoped local reads overlap within one task, including successors whose own dependencies have completed. Mutation/approval admission remains serial within a task. A first-party effect arbiter now gives compatible prepared effects from different active tasks up to four shared dispatch slots; exact-resource conflicts serialize, and Undo takes a global fence. Measured operation averages influence critical-path ordering; route selection and device performance learning remain open.
- **Local routine learning:** an explicit on-device opt-in records only independently requested, fully verified procedures from a strict low-risk action allowlist. Three examples surface the observed request and steps for review; exact reviewed requests can use a newly bound action graph without another planner call. Every run receives a fresh resource contract and goes through normal policy, broker and verification gates. Routine runs cannot reinforce themselves; failed, undone, corrected, retired and forgotten examples cannot strengthen a pattern. A corrected procedure can seed a separate disabled draft only from one unambiguous, current reviewed predecessor with the exact request; three independent verified examples and fresh review remain required. Explicit-reference branch proposals are now implemented as a limited part of feature 35; confidence calibration, authorized automatic prefixes, learned hierarchy and adaptive synthesis remain open.
- **Shared-prefix skills:** two or more separately reviewed routine graphs can expose an exact typed-action/dependency prefix while retaining distinct request aliases and branch suffixes. A bounded local pass groups compatible branches; ambiguous aliases are kept out of a family. Users create a regular disabled skill draft and review it through the existing skill path. The draft digest covers the action graph and every branch's provenance, not observation counts. Learning-off pauses derived skills/workflows/schedules, and forgetting a source deletes the derived skill, disables dependent workflows/schedules and cancels active derived runs. Every run revalidates source lineage under the submission lock and still needs fresh normal resource approval. This uses local SQLite and Rust graph code; it adds no model or service call.
- **Responsiveness:** preparation has its own bounded IPC lane. File preparation/read/verification runs in a bounded blocking pool with an owner deadline. Credential unlock runs outside async executors and owns hydration even after requester cancellation. Other synchronous persistence and mutation calls still need isolation/latency work.
- **Native experience:** macOS and Windows expose preparation previews, execution-stage counts, correction summaries, reviewed-routine steps and explicit review/forget controls. Both keep Stop available during replacement input. The Mac native build passes with Command Line Tools SDK 26.5; Windows XAML parses, but Windows compilation and live UI remain unverified.
- **Controller compilation:** a first-party compiler converts an eligible fully succeeded ProcedureIR run into an unreviewed ControllerIR draft. Checkpoint writes and reads now bind each claimed dispatch UUID to the exact task action and digest in the broker journal; succeeded steps require a confirmed journal entry, the durable independent `VerificationRecord`, and outputs matching the saved task result. Draft compilation accepts a task ID and loads that stored checkpoint instead of trusting a caller-supplied runtime. Each referenced verification observation must match the verifier record's action, target system, timestamp, freshness window, and trusted origin. The compiler preserves typed literal/result inputs, dependencies, output contracts, registered capability IDs, semantic anchors, and evidence; it still rejects streams, branches, repeats, nested skills, task-owned artifacts, unsupported targets, and incomplete runs. ControllerIR schema 2 adds backward-compatible typed input bindings; review and invocation still require separate fresh revalidation and ordinary authority gates. The interpreter and checkpoint writer are not connected to the product task runner, and native review UI/IPC and controller dispatch remain open.
