# Sage first-party inference status

Sage does not currently send model requests to hosted services or launch an external model runtime. Product startup selects `UnconfiguredModelProvider`, endpoint/API-key controls are removed from the Mac and Windows settings UI, protocol-v2 provider-save commands are rejected, connection probes return disabled, and former model-profile flags are rejected as unknown arguments. Core no longer loads or returns provider settings. Previously saved endpoint settings or OS keyring entries may remain, but product inference does not read or invoke them; Sage does not delete those credentials automatically.

The initial local target is Qwen3.5-4B, with Sage admission capped at 8K context and 2K output. The [candidate record](../evals/models/qwen3.5-4b-candidate.json) remains `candidate_not_admitted`. Its official configuration describes a 32-layer hybrid of linear-attention and full-attention blocks plus a vision encoder; the implementation must own those operations and their state.

Candidate inference is opt-in through the `qwen35-evaluation` Cargo feature. Normal Sage Core builds omit candidate inference, tokenizer, tensor parsing, and their Metal and system-resource dependencies. The first-party offline package signer is built from the standalone `sage-model-package` crate. CI separately builds and tests the evaluation feature on macOS and Windows. Candidate evaluation does not enable product inference.

The first-party `sage-qwen35-package` tool signs only files whose sizes and SHA-256 digests match that pinned candidate record. Build it with `cargo build -p sage-model-package --bin sage-qwen35-package --release`, then pass the package directory, a trusted signer key ID, and `--signing-seed-stdin`; stdin must contain exactly 32 raw Ed25519 seed bytes from the release secret manager. The tool streams the six exact artifacts in bounded chunks, refuses symlinks and changed files, verifies the generated signature against the corresponding public key, and creates `sage-qwen35-package.json` without replacing an existing file. It never writes the seed. This produces signed candidate provenance only: the public key still must be installed in Sage's application trust set, and signing does not establish numerical parity, task quality, performance, isolation, or model admission.

Current Sage-owned foundations are:

- `model.rs` owns the closed action schema and bounded structured-turn decoder used by Sage's local candidate generator. It admits one answer, one action, or up to eight independent reads, then assigns action IDs and model provenance locally. Model output cannot set targets, verification outcomes, or dependencies; Core resolves those. `streaming.rs` contains Sage's partial-answer extractor, now connected to candidate decoding through a bounded nonblocking cumulative-preview channel; provider-specific SSE framing and hosted transport have been removed. Product startup still selects `UnconfiguredModelProvider`.
- `qwen_prompt.rs` builds first-party planner prompts from the live closed schema and a bounded, typed subset of the current request and evidence. It excludes task identity and route metadata, treats prior tool output and recalled context as untrusted evidence, and reserves output tokens within the candidate's configured context. Its multimodal form identifies up to eight untrusted visual attachments and emits trusted image-pad spans. `Qwen35CandidateModel::generate_turn` runs text-only evaluation; `generate_turn_with_images` prepares explicitly supplied RGB images, bounds aggregate vision work, replaces those spans with package-bound vision embeddings, assigns spatial text MRoPE positions, and passes the mixed sequence through the same closed-turn validator. `inference_lane.rs` keeps one candidate resident on a dedicated thread, permits one active and one queued request, rejects further requests immediately, and propagates dropped-call cancellation. This in-process lane is not an OS isolation boundary or product provider; product generation still requires the isolated worker and an admitted model package.
- `structured_decode.rs` supplies a Sage-written incremental RFC 8259 prefix recognizer and constrained Qwen greedy-generation helpers. The planner-specific helper intersects syntax validation with an incremental automaton compiled from Sage's live closed planner schema, pruning invalid keys, payloads, tool choices, value bounds, and unsafe multi-action batches as tokens are considered. It withholds the end-of-turn token until `validate_turn_json` accepts the complete output under the same schema and action-graph rules as `parse_turn`; final parsing assigns the real task identity and proposal IDs. The tokenizer precomputes raw byte spellings once, bounds each piece to 4 KiB and the table to 64 MiB, indexes pieces by first byte, and exposes borrowed pieces. A reusable 256-bucket merge visits only grammar-permitted prefixes in token-ID order; the mask checks cancellation every 256 candidate pieces and reuses one sorted allow-list buffer across decode steps. Constrained greedy selection visits only permitted IDs on the dense fallback and sparse paths; disallowed logits need not be scanned for finiteness because they cannot affect selection. Synthetic release microbenchmarks cover indexed mask construction and dense constrained selection, but end-to-end generation remains unqualified and disconnected from a persistent inference worker.
- `inference_cpu.rs`: checked scalar reference math, dense projection, ordinary, zero-centered and SiLU-gated RMS normalization, stable softmax, generic interleaved rotary, Qwen split-half partial rotary and three-axis interleaved MRoPE, grouped-query attention, bounded session-local KV and gated-delta state, causal depthwise-convolution history, Qwen gate conversion, batch and incremental grouped-Q4 packing/projection and f16/bf16 conversion. KV storage uses contiguous per-head binary16 banks, allocates lazily, reserves the validated prompt prefix before prefill, grows geometrically during decode, and zeroes old allocations before replacing them. The incremental Q4 builder retains only packed weights, scales and one partial group, with explicit element and 1 GiB compressed-weight limits. The Q4 output-buffer API lets decoder layers reuse projection storage without an output allocation on the CPU path. Double-precision scalar Q4 projection remains the correctness reference.
- `sage-kernels`: first-party AArch64 NEON Q4 projection uses four independent accumulators and SIMD nibble unpacking, with scalar handling for odd row/group boundaries. Each shared quantization-group scale is applied once after vector reduction rather than multiplied across every SIMD lane. Three 101-sample release runs on the local Mac measured a reused-output 2,560×2,560 Q4 projection at median p50/p95 of 0.306/0.597 ms after row parallelism, compared with 0.612/1.003 ms for the recorded single-worker SIMD path. Earlier one-worker scale-hoisting runs measured 0.567/0.642 ms versus a prior 21-sample path at 0.659/0.681 ms; differing sample counts make that comparison indicative. Large full and selected-row projections split independent output rows across at most eight CPU workers; small matrices remain single-threaded, and worker creation failure falls back to the caller. The f64 reference parity check and odd-shape, cross-group, full-row and selected-row tests pass. The same crate accelerates full-attention Q·K scores, contiguous head-major weighted-value sums, and recurrent gated-delta state updates. Across five 101-sample release invocations, median head-major QK/value kernel p50/p95 was 5.236/5.630 ms at 8K, versus 20.269/21.753 ms for identical position-interleaved KV contents; every query-head score and output matched exactly. At 2K, median p50 was 1.224 ms head-major versus 3.224 ms interleaved. This isolates KV-layout kernel traffic, not softmax or full generation; see [`evidence/2026-10-08-head-major-kv`](../evals/evidence/2026-10-08-head-major-kv/measurement.md). Weighted values use bounded stack accumulators and write into the decoder's final attention buffer; wider generic heads use the scalar path. The recurrence uses bounded fixed stack scratch instead of per-head temporary heap vectors; the 32-head fixture removes 66 scratch allocations per token, with no measured latency change at that fixture size. Other architectures use scalar kernels until their own fast paths pass parity and measured performance checks. These are kernel-only results; full model speed and quality remain unqualified. Details and run values are in [`evidence/2026-10-07-q4-row-parallelism`](../evidence/2026-10-07-q4-row-parallelism/measurement.md).
- Constrained Qwen generation keeps only the final prompt hidden state instead of computing and discarding full-vocabulary logits for every prompt token. At each decode step, if Sage's grammar supplies at most half of the vocabulary as valid next tokens, the tied Q4 output head projects only those rows; the AArch64 path uses the same NEON row kernel as dense projection, while the Metal-backed evaluation matrix reads selected rows directly from immutable shared storage without per-weight bridge calls. Sorted allow-lists preserve the full-projection greedy result and lower-token-ID tie break; unconstrained and larger allow-lists use the dense path. Three release runs over a synthetic packed fixture with the exact 248,320×2,560 Qwen geometry measured across-run median p50/p95 of 58.386/62.198 ms dense versus 29/62 µs for 64 selected rows. A separate three-run crossover sweep measured the selected path at 31.966/54.211 ms p50/p95 for 131,072 rows, versus 55.176/75.794 ms dense, and sets the conservative half-vocabulary cutoff. These are output-head-only synthetic results; they do not measure a loaded checkpoint, full generation, or task quality. Details are in [`evidence/2026-10-07-sparse-vocabulary-projection`](../evals/evidence/2026-10-07-sparse-vocabulary-projection/measurement.md).
- `sage-metal`: a first-party Objective-C/Metal bridge compiles Sage's bounded grouped-Q4 projection kernel on the native Metal device. Each threadgroup handles one output row, distributes columns across a SIMD group, and reduces the partial sums on-device. An explicitly opted-in evaluation loader stores immutable packed weights and scales in CPU-readable `MTLStorageModeShared` buffers, so inference does not retain a second full CPU copy; the same matrix type dispatches projections to Metal and keeps bounded CPU row reads for token embeddings. Metal command failures are surfaced instead of silently accepted as valid model output. Metal remains an optional evaluation route; the product remains on `UnconfiguredModelProvider`, and the Qwen loader remains evaluation-only.
- `inference_resources.rs`: shared cooperative memory reservations for model and isolated compute work, with checked memory envelopes. These estimates reject over-admission but are not OS-enforced quotas and do not start or supervise an inference worker.
- `crates/sage-model-package/src/safetensors.rs`: bounded header validation and chunked f16/bf16/f32 reads from an already-open model shard, isolated from Core task authority.
- `crates/sage-model-package`: Sage's closed v2 manifest for the exact pinned revision, Ed25519 verification against an application-supplied compiled trust set, and streaming SHA-256 verification of the config, tokenizer, image preprocessor, index, and two exact shard filenames. Small artifacts can be read and retained as the exact hashed bytes; larger shards can retain the same open handle for later bounded reading. The verified marker proves signature and bytes only; there is no production Sage signing key, no evaluation-approved package, and no checkpoint is admitted.
- `qwen35.rs` and `qwen35_loader.rs`: strict validation of the selected text/vision tensor geometry, the closed 738-name/two-shard weight index, and checked shapes for every attention, MLP and norm tensor. The candidate loader binds parsed config, tokenizer, image preprocessor and index bytes to one signed manifest, consumes both already-hashed open shard handles, validates both complete safetensors headers, streams rank-2 text and vision projections directly into Q4, imports recurrent/normalization tensors plus the patch projection and learned position table as f32, and assembles all 32 text layers and 24 vision blocks with their patch merger. Its memory estimate covers both weight sets, text state, bounded image activations and runtime; both same-open shard handles are rehashed before returning the candidate. The result is an **unadmitted evaluation candidate**, not a product model, and no real checkpoint has been loaded or parity-tested.
- `qwen35_vision.rs` and the Qwen decoder: parse the signed image-preprocessor profile, prepare bounded normalized RGB patches, emit patch features and axial positions in Qwen's 2×2 spatial-merge block order, and create merged-token text MRoPE positions. `Qwen35VisionEncoder` composes patch projection, learned `[48×48,1024]` bilinear aligned-corner positions, the 24-block scalar stack, and the 2×2 merger into zeroizing text-width embeddings. `Qwen35VisionBlock` implements LayerNorm, fused QKV, per-image non-causal attention, axial RoPE, residual projection and tanh-GELU MLP; the merger normalizes patch rows before grouping and projection. Mixed prompt prefill validates image-pad spans, hidden widths, token positions and total context before advancing any decoder cache; generated text continues at the spatially advanced MRoPE position. Scalar attention and candidate image work have explicit operation bounds. Image decoding, processor parity, checkpoint parity, Metal acceleration for vision and non-Q4 operations, and product-worker integration remain open.
- The Qwen text path composes portable reference math with selected AArch64 NEON fast paths for grouped-Q4 projections, full-attention score/value kernels, and gated-delta recurrence. It supplies one-token linear-attention and full-attention sublayers with Sage-owned f32 or grouped-Q4 projections. Full attention includes per-head zero-centered Q/K normalization, 64-of-256 split-half RoPE, gated grouped-query attention, and a lazy zeroizing binary16 KV cache with contiguous per-head banks; kernels widen values to f32 for attention arithmetic. Eight full-attention layers at the 8K limit have a 256 MiB theoretical binary16 KV footprint, down from 512 MiB with f32 storage; model construction allocates none of it, and prompt prefill reserves only its validated prefix. Five 101-sample runs measured a 74% reduction in 8K synthetic QK/value kernel p50 with the head-major layout versus position-interleaved storage, with exact synthetic score/output equality; full-model impact and task quality remain unmeasured. `Qwen35DecoderLayer` composes either mixer with zero-centered pre/post norms, residuals, and the gated MLP. Each CPU decoder layer reuses zeroizing gate, up, and feed-forward buffers, eliminating 96 projection-result allocations per token across the 32-layer profile; this reserves 2,686,976 bytes, included in the software memory estimate. Failure paths clear the buffers and attention cache. Three alternating release microbenchmark runs on the Apple M3 show essentially unchanged Qwen-sized single-projection p50 (587 μs allocating versus 588 μs reused); p95 is noisy and inconsistent. This confirms allocation removal, not a measured end-to-end speedup. Details are in [`evidence/2026-10-07-q4-output-reuse`](../evals/evidence/2026-10-07-q4-output-reuse/measurement.md). The Metal evaluation bridge still stages projection outputs through host vectors. `Qwen35TextDecoder` applies the zero-centered final norm and tied embedding output projection, and `generate_greedy` bounds output at 2K tokens with allowed-token sets, stop IDs, cancellation checks and cache cleanup. The evaluation path does not yet have checkpoint parity, and binary16 cache quality remains subject to checkpoint evaluation.
- `crates/sage-qwen-tokenizer`: a standalone Sage-written parser for the pinned BPE artifact, Unicode 15 NFC/property tables, ByteLevel mapping, ranked BPE merges, bounded text encode/decode, and Qwen chat framing. It depends only on serde and serde_json; Core re-exports its API for compatibility, and message bodies remain literal text.

The full candidate loader has not imported the 9.3 GB checkpoint's weight tensors. On 7 October, the release-mode shard check verified the six pinned artifact digests and validated all 738 tensor headers across 9,319,737,856 indexed weight bytes; it completed in 22.28 seconds without loading model tensors. The later end-to-end load attempt happened before binary16 KV storage and the resource governor rejected its then-current 4,629,776,384-byte 8K text/vision envelope on this 8 GiB Mac before tensor import. The current profile test estimates 4,364,716,032 bytes with binary16 KV storage, four-head grouped attention scratch, fixed 2,048-position score blocks, and 2,686,976 bytes of reusable decoder MLP scratch; this remains a software estimate, not a hardware measurement or qualification. The grouped attention path measured separately from full-model inference on the Apple M3 and does not qualify this memory estimate. The prior refusal preserves the 16 GiB acceptance requirement, and no post-change checkpoint load or generation has been attempted. No production Sage trust root or evaluation-approved package exists, so product startup remains on `UnconfiguredModelProvider`. The recurrent/KV implementation and tensor-to-layer wiring still have no checkpoint-parity evidence. Tokenizer corpus/reference-vector coverage, image-preprocessor parity, vision numerical parity, real-image task quality, persistent worker, Metal coverage beyond the first Q4 projection, Q4 task-quality evaluation, and measured candidate cold/warm latency and peak memory remain open. Open-ended model tasks therefore report local unavailability.

The current development Mac has 8 GB RAM. It can support source development but cannot close the plan's 16 GB hardware acceptance gate. Sage must qualify the first-party worker on an actual 16 GB Mac before advertising it, then separately qualify Windows and iPhone/iPad companion behavior. See the [continuous-agency ledger](v3/continuous-agency.md) for remaining work.

## Pinned checkpoint artifact smoke tests

Sage's validators can be exercised against small metadata artifacts from the exact revision pinned by `evals/models/qwen3.5-4b-candidate.json`. Download the pinned [`config.json`](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/config.json), [`model.safetensors.index.json`](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/model.safetensors.index.json), and [`preprocessor_config.json`](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/preprocessor_config.json). Their SHA-256 values are `ddc63e1c717afa86c865bb5e01313d89d72bb53b97ad4a8a03ba8510c0621670`, `cf3f798ee02ba45f9622aa8892a47369ab667d0afbf154ee7c2212de42e6302d`, and `27225450ac9c6529872ee1924fcb0962ff5634834f817040f444118116f4e516`, respectively. Run:

```sh
SAGE_QWEN35_CONFIG_JSON=/path/to/config.json \
SAGE_QWEN35_INDEX_JSON=/path/to/model.safetensors.index.json \
cargo test -p sage-core --features qwen35-evaluation --lib qwen35::tests::pinned_checkpoint_metadata_matches_closed_qwen_profile -- --ignored --exact
```

This verifies Sage's closed text/vision architecture profile, 8K admitted context, multimodal IDs, complete 738-entry tensor-name map, shard assignment, and total weight size. It does not read tensor bytes or establish checkpoint parity.

The pinned index can also drive Sage's real-candidate memory estimate:

```sh
SAGE_QWEN35_INDEX_JSON=/path/to/model.safetensors.index.json \
SAGE_QWEN35_PREPROCESSOR_JSON=/path/to/preprocessor_config.json \
cargo test -p sage-core --features qwen35-evaluation --lib qwen35::weight_loader::tests::pinned_checkpoint_memory_envelope_fits_the_initial_16_gib_tier -- --ignored --exact
```

This parses the index and image preprocessor through a temporary test-signed package, checks the Q4 candidate's memory envelope against the initial 8 GiB compute budget reserved on a 16 GiB desktop, and runs the real profile over a constant RGB image to verify resize dimensions, patch grid, token count, and normalization. It does not load model weights, establish image-processor parity, or imply that this 8 GiB development Mac passes the hardware gate.

The first-party tokenizer can be exercised against the exact 12.8 MB [`tokenizer.json`](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/tokenizer.json). Its SHA-256 must be `5f9e4d4901a92b997e463c1f46055088b6cca5ca61a6522d1b9f64c4bb81cb42`. Run:

```sh
SAGE_QWEN35_TOKENIZER_JSON=/path/to/tokenizer.json cargo test --offline -p sage-qwen-tokenizer --lib pinned_checkpoint_tokenizer_matches_slow_bpe_reference -- --ignored --exact
```

This ignored test verifies the artifact digest, vocabulary size, selected structural token IDs, BPE output against a simple first-party merge loop, and NFC encode/decode behavior across whitespace, contractions, accented text, CJK, emoji, numbers, and literal token spellings. A separate boundary test checks selected cases against the pinned split pattern. The reference loop shares Sage's normalization and pre-token segmentation, so full tokenizer reference-vector and corpus conformance remains open.

After placing all six files from the exact pinned revision in one directory, validate the real shard bytes and all indexed tensor headers without importing tensors:

```sh
SAGE_QWEN35_PACKAGE_DIR=/path/to/qwen3.5-4b-851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a \
cargo test -p sage-core --features qwen35-evaluation --lib --release qwen35::weight_loader::tests::pinned_checkpoint_shard_headers_match_the_first_party_tensor_map -- --ignored --exact --nocapture --test-threads=1
```

The check opens each artifact once, checks its size against Sage's candidate record, signs a temporary package using the pinned digests and a deterministic test-only key, then verifies each exact open handle and validates the shard headers against Sage's complete closed tensor map. It avoids a separate pre-hash pass over the 9.3 GB shards. That test key is not a product trust root. On a machine with enough admitted memory, the separate end-to-end candidate check loads the text and vision weights with Sage's Q4 importer and generates one constrained turn through Sage's Metal backend:

```sh
SAGE_QWEN35_PACKAGE_DIR=/path/to/qwen3.5-4b-851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a \
cargo test -p sage-core --features qwen35-evaluation --lib --release qwen35::weight_loader::tests::pinned_checkpoint_first_party_candidate_loads_and_generates_one_turn -- --ignored --exact --nocapture --test-threads=1
```

The end-to-end test asks Sage's live resource governor to admit the actual host before importing weights and uses the planned 8K context limit. Passing on this 8 GiB development Mac would still not meet the 16 GiB hardware, task-quality, or isolated product-worker acceptance gates.

The small Metal projection parity smoke test can be run on a Metal-capable Mac:

```sh
cargo test -p sage-core --features qwen35-evaluation --lib inference_cpu::tests::metal_q4_projection_matches_the_scalar_reference_and_reuses_shared_weights -- --ignored --exact --nocapture
```

It compares one synthetic odd-shaped Q4 matrix against Sage's scalar reference and reads back an embedding row after moving the backing weights into shared Metal storage. It does not load Qwen weights or demonstrate model checkpoint parity.

The release measurement for a Qwen hidden-size projection uses 101 alternating samples per path:

```sh
cargo test --release -p sage-core --features qwen35-evaluation --lib inference_cpu::tests::qwen_hidden_q4_projection_latency_measurement -- --ignored --exact --nocapture
```

On 7 October 2026, three release runs on the local 8 GiB Apple M3 measured NEON CPU p50/p95 at 0.566–0.570/0.626–0.653 ms for a synthetic 2,560×2,560 matrix. The prior 21-sample SIMD run measured 0.659/0.681 ms. The same 101-sample runs measured Metal at 5.501–5.610/7.521–7.814 ms, so this single-projection Metal dispatch remains slower for this fixture and stays opt-in for evaluation. Measurements include allocation, command submission, completion, and buffers; they exclude checkpoint loading, other model operators, prompt processing, and end-to-end generation. The CPU scale-hoisting results are recorded in [`evals/evidence/2026-10-07-q4-scale-hoist/measurement.md`](../evals/evidence/2026-10-07-q4-scale-hoist/measurement.md); the earlier Metal kernel revision measurements and their limits are in [`evals/evidence/2026-10-07-metal-q4/projection-measurement.md`](../evals/evidence/2026-10-07-metal-q4/projection-measurement.md).
